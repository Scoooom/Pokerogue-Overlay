PokéRogue
Overlay

A local Node.js server that reads your live PokéRogue game state and serves browser-source-ready overlay pages for OBS and other streaming software. Fully themeable with CSS variables.

↗ GitHub Quick Start CSS Variables

Overview

🃏
Party Strip & Cards
All 6 slots with sprite, name, level, types, ability, passive, tera type, status, stat stages, HP bar, and 4 moves. Single-slot cards available too.
🌊
Wave Widget
Current wave, biome, and next encounter countdown. Full Classic mode battle map — rival, evil team, gym leaders, Elite Four, Eternatus.
📊
Run Stats
Wave, biome, live timer, money, shiny count, alive count, and run name. Timer counts up between server polls.
🖼️
Sprite Proxy
Server-side Showdown CDN resolution with form-aware fallback chain and in-memory caching. No flickering.
🎨
Fully Themeable
60+ CSS variables covering every colour, size, and radius. Override in OBS Custom CSS or a local custom.css file.
🔄
Auto-updating Script
Tampermonkey script auto-updates from GitHub. Uses only window.gameInfo — the official PokéRogue extension API.

Installation

Requirements

Node.js 18 or later. Git optional (you can also download a ZIP).

1. Clone and start the server

git clone https://github.com/Scoooom/Pokerogue-Overlay.git -b v2
cd Pokerogue-Overlay
npm install
node server.js

The server starts at http://localhost:3000. Open that address for the interactive setup page.

2. Install the Tampermonkey script

Install the Tampermonkey browser extension, then add the script:

https://raw.githubusercontent.com/Scoooom/Pokerogue-Overlay/refs/heads/v2/tampermonkey.user.js

The script auto-updates from GitHub whenever a new version is pushed — no manual reinstall needed.

3. Play PokéRogue

Go to pokerogue.net with Tampermonkey enabled. The script will start sending data to the local server automatically.

4. Add OBS browser sources

In OBS, add a Browser Source for each overlay you want. Point it at the relevant URL below.

/party

6-slot party strip. Each card shows: sprite, name/nickname, level, types, ability, passive ability, tera type, status condition, stat stages (all 7, always visible), HP bar with HP numbers, and all 4 moves with type-coloured dots. Fainted Pokémon are dimmed.

ParamTypeDescription
layoutstringhorizontal (default, ~840px wide) or vertical (320px wide, 2×2 move grid)

/card

Single Pokémon card. Uses the exact same renderer as /party — any CSS change applies to both automatically via shared card-shared.js and card-shared.css.

ParamTypeDescription
slot0–5Party slot to display. Default: 0.

/wave

Compact wave widget. Shows wave number, biome name, game mode badge, and a colour-coded next-encounter chip. Covers all Classic mode fixed battles:

  • 🤝 Rival — waves 8, 25, 55, 95, 145, 195
  • 😈 Evil Grunts — waves 35, 62, 64, 66, 112, 114, 164
  • 💀 Evil Leaders — waves 115, 165
  • 🏅 Gym Leaders — C-20: 20,50,80,110,140,170 · C-30: 30,60,90,120,150,180
  • ⚔️ Elite Four — waves 182, 184, 186, 188
  • 👑 Champion — wave 190
  • ☄️ Eternatus — wave 200
  • ⭐ Wild Boss — every other 10th wave
ParamTypeDescription
cycle20 | 30Gym leader cycle. Omit for unknown — possible gym waves shown as (?). Set once per run in the OBS source URL.
buttonsflagShow C-20 / C-30 / ? cycle selector buttons. Hidden by default — useful in a browser window, not needed for OBS.
Gym cycle tip: At the start of each run, note whether your first gym appears at wave 20 or 30. Right-click your OBS wave source → Properties → update the URL to /wave?cycle=20 or /wave?cycle=30.

/stats

Run stats panel showing: wave, biome, game mode, live timer (counts up between server polls using play time as base), shiny count, alive count, money (₽), and run name (shown only when set, e.g. "Mono Type").

/full

The original full-featured overlay. Shows all 6 party slots with an inline editor — click EDIT on any Pokémon to manually adjust moves, ability, passive, or nature. Useful if the game doesn't expose certain fields via window.gameInfo.

/sprite

Sprite endpoint. Server-side resolves sprites from the Pokémon Showdown CDN with a form-aware fallback chain (gen5 → gen5ani → gen8). Results are cached in memory by name+form.

ParamTypeDescription
slot0–5Dynamic slot lookup. Polls /data every second and swaps the image when the Pokémon changes. Use as an OBS browser source.
namestringIdentity-based lookup. Browser caches indefinitely per Pokémon — no flickering. Use inside <img src> tags.
formstringForm suffix (e.g. crowned, mega). Empty for base form. Used with name.
rawflagReturn raw image bytes instead of an HTML wrapper page.

API Routes

/data

Returns normalised game state JSON. Includes wave, biome, gameMode, playTime, money, runName, gymCycle, and the full party array. Each Pokémon has: name, form, level, hp/maxHp, types, moves (with types), ability, passive, passiveEnabled, nature, status, statStages, teraType, isTerastallized, shiny, variant, isFusion.

/raw

Returns the exact window.gameInfo payload received from the Tampermonkey script plus a receivedAt timestamp. Useful for debugging normalization or discovering new fields as the game updates.

/names[?slot=N]

Returns party slot names. Without slot param returns all 6 as an array. With ?slot=N returns { slot, name }. Empty slots return null.

Customization

Every visual property is defined as a CSS custom property (variable) in theme.css, which is loaded by every overlay page. Override any variable to change the look.

How it works

CSS variables are defined with defaults in theme.css. Your overrides go in :root { } and win via standard CSS cascade. You can override from two places:

Option 1 — custom.css file

Create a custom.css file in the project root. It is served by the server and loaded by every page. It is gitignored so it stays local to your machine.

cp custom.css.example custom.css
# Edit custom.css — changes apply immediately on next page load

Option 2 — OBS Custom CSS

In OBS: right-click a browser source → Properties → scroll to Custom CSS. Overrides apply only to that source.

:root {
  --color-accent: #ff6b6b;
  --border-radius-card: 0px;
  --bg-card: rgba(0, 0, 0, 0.95);
}

Type Colours

Every Pokémon type has its own CSS class (.type-FIRE, .type-WATER, etc.) with RGB component variables (--tr, --tg, --tb). Override any type colour in custom.css:

/* Change Fire type to a brighter orange */
.type-FIRE { --tr: 255; --tg: 90; --tb: 0; }

/* Make Psychic type hot pink */
.type-PSYCHIC { --tr: 255; --tg: 0; --tb: 128; }

This affects type badges, move dots, tera badges — anywhere that type's colour appears.

Architecture

PokéRogue tab
  └── Tampermonkey script (reads window.gameInfo, POSTs every 1s)
        └── POST /update → Node.js server (server.js)
              ├── Normalises game state (moves, types, abilities…)
              ├── Decrypts nothing — uses only the official gameInfo API
              ├── Resolves sprites from Showdown CDN (cached in memory)
              └── Serves overlay pages
                    ├── /party, /card    → card-shared.js + card-shared.css
                    ├── /wave            → wave.html
                    ├── /stats           → stats.html
                    ├── /full            → overlay.html
                    └── /sprite          → slot or name+form based
