Documentation

PokéRogue Overlay is a local Node.js server that reads game state from a Tampermonkey script and serves browser-source-ready overlay pages for OBS and other streaming software.

Overview

The system has three parts: a Tampermonkey script running in your browser that reads window.gameInfo and POSTs it to the local server every second; a Node.js server that normalises the data, resolves sprites, and serves overlay pages; and a set of HTML pages you add as OBS browser sources.

Installation

Requirements

Node.js 18 or later. Clone the repo and install dependencies:

git clone https://github.com/Scoooom/Pokerogue-Overlay.git -b v2
cd Pokerogue-Overlay
npm install
node server.js

The server runs at http://localhost:3000. Visit that address to see the setup page.

Tampermonkey

Install the Tampermonkey browser extension, then install the script directly from GitHub — it will auto-update whenever a new version is pushed:

https://raw.githubusercontent.com/Scoooom/Pokerogue-Overlay/refs/heads/v2/tampermonkey.user.js

The script sends window.gameInfo — the official extension API exposed by the PokéRogue devs — to the local server once per second. No private data is read or transmitted outside your machine.

/full

Full-featured party overlay. Shows all 6 party slots with sprite, name, level, types, ability, passive, nature, tera type, status, stat stages, HP bar, and 4 moves. Includes an inline editor for manual data correction. Recommended OBS size: 860×520px.

/party

6-slot party strip using the shared card renderer. Supports two layouts:

ParameterTypeDescription
layoutstringhorizontal (default) or vertical. Vertical is 320px wide, horizontal is ~840px wide.

Recommended OBS size: 840×175px horizontal, 320×510px vertical.

/card

Single Pokémon card. Same rendering as /party — shares card-shared.js and card-shared.css. Any style change applies to both automatically.

ParameterTypeDescription
slot0–5Party slot to display. Default: 0.

Recommended OBS size: 320×175px.

/wave

Compact wave widget showing wave number, biome, game mode badge, and a next-encounter chip. Knows all Classic fixed battles — rival, evil team, gym leaders, Elite Four, Champion, Eternatus.

ParameterTypeDescription
cycle20 | 30Gym leader cycle. Omit for unknown — possible gym waves shown as (?). Set once per run in the OBS source URL.
buttonsflagShow the C-20 / C-30 / ? cycle selector buttons. Hidden by default.

Recommended OBS size: 280×140px.

/stats

Run stats panel showing wave, biome, game mode, live timer (counts up between server polls), shiny count, alive count, money, and run name (if set). Recommended OBS size: 230×260px.

/sprite

Sprite endpoint. Server-side resolves the first working Pokémon Showdown CDN image and caches it in memory.

ParameterTypeDescription
slot0–5Slot-based lookup. Dynamic — always reflects current slot contents. Use for OBS browser source.
namestringName-based lookup. Identity URL — browser caches indefinitely per Pokémon. Use inside <img src>.
formstringForm name (e.g. crowned, mega). Empty for base form. Used with name.
rawflagReturn raw image bytes instead of an HTML page.
OBS browser source: use /sprite?slot=0 — polls every second and swaps the image when the Pokémon changes, without a full page reload.

Inside an <img> tag: use /sprite?name=Bramblin&form=&raw — browser-cacheable, no flickering.

API Routes

/data

Returns normalised game state JSON including wave, biome, gameMode, playTime, money, runName, gymCycle, and the full party array with types, moves (with types), ability, passive, stat stages, tera type, and more.

/raw

Returns the exact window.gameInfo payload received from the Tampermonkey script, plus a receivedAt timestamp. Useful for debugging normalization or discovering new fields.

/names[?slot=N]

Returns party slot name(s). Without slot, returns all 6 as an array. With slot, returns a single { slot, name } object. Empty slots return null.

/cycle

GET /cycle returns { cycle: 20 | 30 | null }. POST /cycle with body { cycle: 20 | 30 | null } sets or resets it.

How Customization Works

Option 1 — custom.css file (recommended for development)

Create a custom.css file in the project root. It is loaded by every overlay page automatically and is excluded from git so it stays local to your machine.

/* custom.css — place in the Pokerogue-Overlay folder */
:root {
  --color-accent: #ff6b6b;
  --border-radius-card: 0px;
}

The server returns an empty file if custom.css doesn't exist, so no errors occur.

Option 2 — OBS Custom CSS

Every visual property is defined as a CSS custom property (variable) in theme.css, which is loaded by every overlay page. To override anything, paste your CSS into the Custom CSS field of the OBS browser source.

In OBS: right-click a browser source → Properties → scroll to Custom CSS. Paste your overrides there. Standard CSS cascade applies — your values win over the defaults. 
/* Example — paste into OBS Custom CSS */
:root {
  --color-accent: #ff6b6b;
  --border-radius-card: 0px;
  --bg-card: rgba(0, 0, 0, 0.95);
}

Type Colours

Every Pokémon type has its own CSS class (.type-FIRE, .type-WATER, etc.) with RGB component variables (--tr, --tg, --tb). Override any type colour in custom.css:

/* Change Fire type to a brighter orange */
.type-FIRE { --tr: 255; --tg: 90; --tb: 0; }

/* Make Psychic type hot pink */
.type-PSYCHIC { --tr: 255; --tg: 0; --tb: 128; }

This affects type badges, move dots, tera badges — anywhere that type's colour appears.
